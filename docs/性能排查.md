# 性能排查手册

页面"切换 tab 要 5 秒"这类问题，不要猜。按下面的顺序看一眼就能定位到具体是哪一层。

## 一、先跑诊断脚本（最快）

部署后在服务器上执行：

```sh
python3 tools/diag.py https://你的域名
# 如果后端端口可直接访问，把后端也带上，信息更全：
python3 tools/diag.py https://你的域名 http://127.0.0.1:3000
```

它会逐层打印：

| 项 | 含义 | 慢说明什么 |
|---|---|---|
| 【1】后端进程状态 | worker 池存活数、内存、Python 版本 | 存活数 < 常驻数 → 进程在被反复重建 |
| 【2】后端直连 | 纯计算耗时 | 慢 → 后端自己的问题 |
| 【3】经 Next 代理 | 浏览器实际请求的地址 | 慢 → Next 转发 / 网络链路 |
| 【4】连续切换 | 轮动 → MA200 来回切 | 慢 → 切换时的并发或重复请求 |
| 【5】首页 HTML | Next 服务端渲染 | 慢 → Next 生产进程本身 |

## 二、看后端日志

每条日志都带 `[时间][线程]` 前缀，按下面几个关键词搜：

```sh
# 每个策略请求的进出与耗时
grep "请求←" 日志

# 每次脚本执行：耗时 + 走的是哪条路
grep "\[脚本" 日志
#   via=池内worker        正常，几十到几百毫秒
#   via=扩容worker        并发上来了，现开了一个
#   via=临时进程(boot Xs) 池子满了，这次多付了 X 秒启动
#   via=重建后重试(...)   worker 刚死过，这次用了新进程

# worker 的出生与死亡——最重要
grep "\[池\]" 日志
```

`[池]` 日志的判读：

```
[23:23:50][池] Worker#2 退出 pid=747021 rc=-9 存活 16.7s
```

- `rc=-9`（或 137）→ 被 **SIGKILL**，容器里几乎只有一种原因：**内存不足被 OOM 杀掉**
- `存活` 只有几十秒 → 在**被反复重建**，这正是"每次打开都要好几秒"的根源
- 若日志里 `Worker#N 启动` 频繁出现且编号一路涨，同样说明进程在反复死

```
[23:25:45][池] calculate_momentum_joinquant.py 等 worker 用了 0.60s（池内 5）
```

- 出现这条说明请求在**排队**等 worker。池内数量已到上限还在等，说明并发确实高
- 如果这条动辄 3~5 秒，那就是"页面慢但 CPU 不忙"的直接原因

## 三、看响应头

每个策略接口都会回 `X-Server-Cost`（服务端计算耗时，单位秒），Next 路由原样透传。

浏览器 F12 → Network → 点开 `ma200-trend` 请求：

```
总耗时 5120ms   -   X-Server-Cost: 0.13   =   4990ms  ← 卡在网络/转发/渲染
```

反过来，如果 `X-Server-Cost: 4.8`，那就是后端算得慢，去查上面的 `[脚本]` 和 `[池]` 日志。

## 四、看前端控制台

每次请求会打印一行：

```
[API] /api/strategy/ma200-trend 总耗时 135ms (首字节 133ms, 读body 2ms) | 后端计算 128ms
```

- 首字节慢 + 后端计算小 → 卡在请求发出到响应到达之间（网络、代理、排队）
- 首字节快但读 body 慢 → 响应体过大或连接被限速

## 五、一个命令看池子现状

```sh
curl -s http://后端:3000/api/debug/perf | python3 -m json.tool
```

重点看：

- `workerPool.alive` 是否等于 `workerPool.size`（常驻数）
- `backend.rssMB` 是否已经贴着容器内存上限
- `backend.cpuCount` 是不是只有 1~2 核（低配机器会把启动成本放大好几倍）
- `probe.via` 是 `池内worker` 还是 `临时进程`；`probe.poolElapsed` 是多少
- `probe.新浪实时` 是数据源直连耗时，用来区分"自己慢"还是"外网慢"

## 六、内存估算

worker 常驻内存取决于它跑过什么脚本：

| 跑过的脚本 | 单 worker 内存 |
|---|---|
| 只跑 MA200（仅 requests） | 约 30MB |
| 跑过轮动 / 均值回归 / 超跌（用到 pandas） | 约 130MB |

`WORKER_POOL_SIZE`（常驻）默认 2，`WORKER_POOL_MAX`（上限）默认 6。
容器内存紧张时，把这两个值调小，或直接把 `WORKER_POOL_SIZE=1`。
